# v0.5.4 代码审查报告

审查范围：v0.5.4 版本全部代码（`5908c89..8cd0ff6` + 后续 fix 提交至 `14939be`）
审查重点：代码逻辑合理性、通用性、性能开销、安全性

---

## 一、严重问题（HIGH）

### H1. 命令注入 — `install_agent_command` 无校验执行 PowerShell
- **文件**: `src-tauri/src/lib.rs:573-585`
- **问题**: 前端传入的 `command` 字符串直接传给 PowerShell `-Command` 执行，无白名单、无沙箱。恶意或被篡改的前端可执行任意系统命令。
- **建议**: 建立允许执行的安装命令白名单（如 `npm install -g xxx`、`winget install xxx`），仅允许匹配白名单模式的命令通过。

### H2. 路径遍历 — `read_text_file` 无路径校验
- **文件**: `src-tauri/src/lib.rs:85-106`
- **问题**: 接受任意文件路径参数，可读取系统上任何文件。配合 `read_file_as_base64`（`image.rs:117`）和 `read_image_as_data_url`（`image.rs:151`），构成完整的文件泄露链。
- **建议**: 限制可读路径范围（项目目录、`.claude/`、`.jishu-hub/`），拒绝访问敏感目录。

### H3. 路径遍历 — `save_session_files` 的 label 可包含路径分隔符
- **文件**: `src-tauri/src/image.rs:98`
- **问题**: `filename = format!("{}_{}.{}", index, label, ext)`，若 label 含 `..` 或 `/`、`\`，文件可能写到预期目录之外。
- **建议**: 对 label 做清洗，移除路径分隔符和 `..`。

### H4. `write_text_file` 路径校验不充分
- **文件**: `src-tauri/src/lib.rs:108-128`
- **问题**:
  - Windows 上 `/tmp` 和 `/var/folders` 判断为死代码
  - 允许写入 `.json`、`.toml` 等敏感配置文件
  - 无符号链接保护，home 内的符号链接可指向任意位置
- **建议**: 使用规范路径（canonicalize）后检查前缀；明确限制可写文件类型白名单。

### H5. `find_process_by_resume` 中 session ID 注入 PowerShell
- **文件**: `src-tauri/src/hub.rs:614-628`
- **问题**: session ID 插入 PowerShell 过滤表达式时仅转义了单引号。`*`、`?`、`[` 等 PowerShell 通配符未处理，可能破坏过滤逻辑。
- **建议**: 对 session ID 中的 PowerShell 特殊字符做完整转义，或改用 `-eq` 精确匹配。

### H6. React 闭包过期 — `handleSelectSession` 在 effect 中捕获旧状态
- **文件**: `src/pages/chat-page.tsx:244-248`
- **问题**: `navigateToSession` effect 的依赖数组缺少 `handleSelectSession` 和 `projectId`。函数未用 `useCallback` 包裹，每次渲染重建，effect 中调用时可能使用过期的闭包值，导致选中错误项目的会话。
- **建议**: 将 `handleSelectSession` 用 `useCallback` 包裹，并加入 effect 依赖数组。

## 二、中等问题（MEDIUM）

### M1. 同步 Tauri 命令阻塞异步运行时
- **文件**: `src-tauri/src/lib.rs` 多处
- **问题**: `scan_projects`、`list_sessions`、`agent_refresh_health` 等同步命令在 Tauri 异步线程上执行大量文件 I/O 和进程创建，阻塞其他命令处理。
- **影响**: 多个 UI 操作并发时界面卡顿。
- **建议**: 改为 `async` 命令，用 `tokio::task::spawn_blocking` 包裹阻塞操作。

### M2. `probe_sync` 在已有 Tokio 运行时内创建新运行时
- **文件**: `claude_code.rs:219`、`codex.rs:121`、`opencode.rs:1083`
- **问题**: 每个 agent 的 `probe_sync()` 创建新的 `tokio::Runtime`，在已有运行时上下文中可能 panic 或死锁。
- **建议**: 重构为真正同步的探测逻辑，或使用 `tokio::task::block_in_place`。

### M3. 配置文件读写 TOCTOU 竞态
- **文件**: `config.rs:161-193`、`hub.rs` 全部读写操作
- **问题**: 读-改-写无文件锁，并发保存（如多窗口或快速连续操作）可能丢失数据。
- **建议**: 引入文件锁（`fslock`）或使用原子写入模式（写临时文件 → rename）。

### M4. 非原子文件写入 — 崩溃时数据损坏
- **文件**: `config.rs`、`hub.rs`、`command.rs`
- **问题**: 所有文件写入直接 `std::fs::write`，进程崩溃时文件可能被截断为空。
- **建议**: 统一使用"写临时文件 → rename"模式（`tempfile::persist`）。

### M5. 备份文件无上限累积
- **文件**: `config.rs:195-206`
- **问题**: 每次保存配置创建一个带时间戳的备份文件，无清理机制。长期使用将积累大量备份。
- **建议**: 只保留最近 N 个备份（如 10 个），保存时自动清理旧文件。

### M6. `chat-page.tsx` 过大（1000+ 行）
- **文件**: `src/pages/chat-page.tsx`
- **问题**: 单文件包含侧边栏、会话列表、消息区、流式消息、搜索、访问模式等全部逻辑，难以维护和测试。
- **建议**: 拆分为 `SessionSidebar`、`ChatArea`、`StreamEventHandler` 等子组件。

### M7. 图片缓存无淘汰策略
- **文件**: `src/components/sessions/inline-image.tsx:56`
- **问题**: `imageCache` 为模块级 `Map`，永不清除。长时间运行查看大量图片后，内存持续增长（data URL 体积大）。
- **建议**: 加入 LRU 淘汰或最大条目数限制。

### M8. 流状态 Store 返回新对象引用导致全局重渲染
- **文件**: `src/hooks/use-stream-store.ts:252-256`
- **问题**: `streamStore.getState()` 每次返回新对象（spread 创建），所有 `useSessionStream` 订阅者都在每次 flush 时重渲染，不论其 session 是否变化。
- **建议**: 用 `Object.is` 浅比较或在 Store 层做按 session key 的变更检测。

### M9. 大量硬编码中文字符串绕过 i18n
- **涉及文件**: `chat-page.tsx`、`App.tsx`、`InstallAgentDialog.tsx`、`ToolGroup.tsx`、`projects-page.tsx`、`FileViewerPanel.tsx` 等
- **问题**: 数十处中文字符串直接硬编码或以 Unicode 转义形式写入，不经过 `t()` 翻译函数。英文 locale 下仍显示中文。
- **建议**: 系统性地将所有硬编码中文提取到 i18n 资源文件。

### M10. `commands-page.tsx` 定时器未在组件卸载时清理
- **文件**: `src/pages/commands-page.tsx:35`
- **问题**: `setTimeout(() => setRunningKey(null), 2000)` 未在 unmount 时 clear，React 会在卸载后调用 setState 并警告。
- **建议**: 在 `useEffect` cleanup 中 `clearTimeout`。

### M11. `handlePaste` 中 `files.length` 闭包过期导致文件序号错误
- **文件**: `src/components/sessions/chat-input.tsx:111-231`
- **问题**: 回调依赖 `files.length`，但异步 reader 解析完成时 `files.length` 可能已变化，导致文件索引标签重复或错乱。
- **建议**: 使用 ref 追踪当前文件数量，或在异步回调中获取最新 state。

### M12. 悬浮窗口主题逻辑重复
- **文件**: `src/components/sessions/floating-session.tsx:11-14`
- **问题**: 独立实现主题应用逻辑，未使用 `ThemeProvider`。主题 key 或应用方式变更需同步修改两处。
- **建议**: 抽取共享的主题初始化函数，或让悬浮窗口也接入 ThemeProvider。

## 三、低级问题（LOW）

### L1. `check_prerequisite` 仅限 Windows
- **文件**: `src-tauri/src/lib.rs:564-570`
- **问题**: 使用 `where` 命令检测工具是否存在，macOS/Linux 需用 `which`。非 Windows 平台始终返回 false。
- **建议**: 添加 `#[cfg]` 平台条件分支。

### L2. `now_ms()` 函数重复定义 5 次
- **文件**: `mod.rs:199`、`claude_code.rs:503`、`codex.rs:663`、`opencode.rs:1441`、`discovery.rs:177`
- **建议**: 提取到公共工具模块。

### L3. `AgentInfo` 在两个文件中定义
- **文件**: `agent/mod.rs:18-25`、`agent/capability.rs:39-64`
- **建议**: 统一为一处定义。

### L4. `displaySessions` 未用 `useMemo` 包裹
- **文件**: `src/pages/chat-page.tsx:173-178`
- **问题**: 每次渲染创建新数组，触发下游组件不必要重渲染。
- **建议**: 用 `useMemo` 包裹计算逻辑。

### L5. 缺少 React Error Boundary
- **问题**: 组件树中无任何 `ErrorBoundary`。任何组件渲染异常（如畸形消息解析失败）将导致整个应用白屏。
- **建议**: 在关键位置（如消息列表、配置面板）添加 Error Boundary。

### L6. `CopyButton` 中 `setTimeout` 未在卸载时清理
- **文件**: `src/components/sessions/message-view.tsx:162`
- **建议**: 使用 ref 存储 timeout ID，在 useEffect cleanup 中清除。

### L7. `add-project-dialog.tsx` 含调试 `console.log`
- **文件**: `src/components/projects/add-project-dialog.tsx:26-29`
- **建议**: 移除生产代码中的 console.log。

### L8. ConfigForm 列表使用数组索引作为 key
- **文件**: `src/components/config/config-form.tsx:342,369`
- **问题**: 使用 `idx` 作为 key，列表增删时可能导致 React reconciliation 错误。
- **建议**: 使用内容本身（如 pattern 字符串）作为 key。

### L9. `encode_project_path` / `decode_project_path` 有损编码
- **文件**: `src-tauri/src/project.rs:345-351`
- **问题**: `\` 和空格都映射为 `-`，解码时无法区分。文件系统匹配可缓解但目录删除后回退路径将出错。
- **建议**: 考虑使用 URL 编码或 Base64 编码避免歧义。

### L10. 多处重复的 click-outside 监听模式
- **涉及文件**: `App.tsx`、`chat-input.tsx`、`AgentSwitcher.tsx`、`project-card.tsx`
- **建议**: 提取为公共 `useClickOutside` hook。

### L11. `get_level1_dir` 假定 Windows 路径结构
- **文件**: `src-tauri/src/project.rs:357-371`
- **问题**: 假定路径组件为 `Prefix + RootDir + Normal`，Unix 路径无 Prefix 组件，始终返回 None。

### L12. 互斥锁中毒静默恢复
- **文件**: `src-tauri/src/agent/mod.rs:86,142,192`
- **问题**: `unwrap_or_else(|e| e.into_inner())` 静默使用可能损坏的数据，无日志记录。
- **建议**: 至少记录 warn 日志。

## 四、总结

| 严重级别 | 数量 | 主要类别 |
|---------|------|---------|
| HIGH    | 6    | 命令注入、路径遍历、React 闭包过期 |
| MEDIUM  | 12   | 竞态条件、阻塞运行时、文件安全、组件过大、i18n 缺失 |
| LOW     | 12   | 代码重复、跨平台适配、小性能优化 |

### 优先修复建议

1. **安全加固**（H1-H5）: 输入校验、路径限制、命令白名单 — 桌面应用虽不像 Web 应用那样暴露，但仍应遵循最小权限原则
2. **原子写入**（M4）: 全局替换为"写临时文件 + rename"模式，防止崩溃时配置丢失
3. **异步化阻塞操作**（M1）: `scan_projects`、`list_sessions` 等改为异步，避免 UI 卡顿
4. **i18n 统一**（M9）: 系统性提取硬编码中文到翻译文件
5. **chat-page.tsx 拆分**（M6）: 按功能模块拆分为独立组件，降低维护复杂度
