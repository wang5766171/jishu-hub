# 任务主工作台与统一任务图

本目录保存 v0.6.x 任务功能的调研、历史方案、评审记录、最终设计、**UI 美化设计稿**和开发记录。

任务功能尚未正式发布，当前设计不承担旧任务、旧表、旧状态或旧交互的兼容责任。后续开发应以"任务主工作台 + 统一任务图 + 本地事件驱动运行时"为目标。

> **2026-06-24 方向调整**：任务三阶段（需求讨论→流程规划→流程执行）的推进机制，从"Hub 层脚本/事件驱动"改为"Pi 原生扩展驱动"。主流程由 Pi 扩展（`jishu-task-conductor`）确定性推进，产出物内容由 skill 驱动，执行由外部注册的执行器（`jishu-task-executor`）实现。详见下方「扩展机制实现流程」章节。

> **📌 新增：UI 美化设计方案与交互原型** — 详见下方「UI 设计稿」章节，包含完整的对话式规划、增强画布、节点检查器/执行监控、分屏模式四阶段 HTML 原型，均支持三套主题实时切换。

## 已确认的关键决定

- 流程图是任务主工作台，不是列表的附属视图。
- 使用分层复合任务图和不可变 Revision。
- 调度采用最大安全并行。
- 运行事实使用追加式 TaskEvent。
- AI 与手工编辑共享 GraphCommand，并先展示 Diff。
- Agentic Loop 位于 Attempt 内；持久化循环使用 `Control::Loop`。
- 负责人机器掌握完整图、调度、SQLite、事件、审批和预算。
- 多机器仅预留 Lease 执行边界，当前不做过度设计。
- 目标支持 500 个可执行节点的连续语义画布。
- 旧任务数据直接废弃，不提供转换工具。
- ACP/Pi RPC 事件出口用回调 `Arc<dyn Fn>`（不用 enum sink）——规避 Windows 工具链加载 bug。
- PiRpc 走持久会话实时流式（不走阻塞）——规划阶段用户可实时看到 agent 输出。
- steer 用 Pi 原生 `{"type":"steer"}` 命令（不用 prompt）。
- 节点位置持久化到 localStorage（不写入 GraphRevision）。
