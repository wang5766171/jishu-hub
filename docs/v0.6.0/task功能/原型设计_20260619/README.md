---

## 核心设计原则

### 会话能力完全复用，不重复实现

**这是本设计最核心的原则。** 任务模式不新做任何对话页面或输入组件，所有对话能力均复用应用已有的统一会话组件（`ChatInput`、`MessageView`、`StreamingMessage`、`streamStore`）。任务专属能力（阶段导航、需求终稿卡片、流程画布等）作为按需挂载的 slot/adapter 嵌入会话流中。

详见 `任务会话核心复用审查说明_20260620.md` 和 `prototype_v2/交互说明_v2.md`。

## 任务三阶段流程

每个任务实例遵循三阶段流程：

| 阶段 | 对应场景 | 说明 |
| --- | --- | --- |
| **阶段一：需求讨论** | 场景 ② | 多轮对话澄清需求，同一会话内完成需求终稿确认 |
| **阶段二：流程规划** | 场景 ③ | 读取需求终稿，生成并确认执行流程 |
| **阶段三：任务执行** | 场景 ④ | 执行流程节点，实时监控与干预 |

**阶段回溯：** 任务执行阶段可通过阶段导航回溯查看需求讨论和流程规划的历史会话。

## 核心结论

### 会话复用

- **任务模式必须复用常规会话核心能力**，任务专属能力只能作为按需组件、工具或 slot 注入。
- 不新做任何对话页面或输入组件，所有对话能力来自统一会话组件。

### 任务流程

- 任务从真实会话开始，不是独立表单流程。
- 需求讨论的结果形成需求终稿（固定目录文件），流程规划阶段读取该文件。
- 任务生成后进入流程页面，清晰展示节点职责、依赖关系、执行状态和可干预会话。

### 数据管理

- 任务模式与常规会话在列表和数据归属上分离。
- 删除任务必须删除完整数据，不只是主记录。
