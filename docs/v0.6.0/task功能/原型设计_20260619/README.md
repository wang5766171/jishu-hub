# 任务功能设计文档目录说明

> 本目录沉淀 v0.6.0 任务功能的完整设计资料，包括设计方案、交互原型、实施计划和技术契约。

## 核心设计原则

### 会话能力完全复用，不重复实现

**这是本设计最核心的原则。** 任务模式不新做任何对话页面或输入组件，所有对话能力均复用应用已有的统一会话组件（`ChatInput`、`MessageView`、`StreamingMessage`、`streamStore`）。任务专属能力（阶段导航、需求终稿卡片、流程画布等）作为按需挂载的 slot/adapter 嵌入会话流中。

详见 `任务会话核心复用审查说明_20260620.md` 和 `prototype_v2/交互说明_v2.md`。

## 任务三阶段流程

每个任务实例遵循三阶段流程：

| 阶段 | 对应场景 | 说明 |
| --- | --- | --- |
| **阶段一：需求讨论** | 场景 ② | 多轮对话澄清需求，同一会话内完成需求终稿确认 |
| **阶段二：流程规划** | 场景 ③ | 读取需求终稿，生成并确认执行流程 |
| **阶段三：任务执行** | 场景 ④ | 执行流程节点，实时监控与干预 |

**阶段回溯：** 任务执行阶段可通过阶段导航回溯查看需求讨论和流程规划的历史会话。

## 核心结论

### 会话复用

- **抽取共享 useChatSession** — 从 chat-page 抽取通用会话 hook，三阶段 + 常规会话统一消费。
- 新会话能力只在一处增强，chat-page 后续新增能力只需改 useChatSession。
- 不新做任何对话页面或输入组件，所有对话能力来自 useChatSession。

### 任务流程

- 任务从真实会话开始，不是独立表单流程。
- 需求讨论的结果形成需求终稿（固定目录文件），流程规划阶段读取该文件。
- 任务生成后进入流程页面，清晰展示节点职责、依赖关系、执行状态和可干预会话。

### 数据管理

- 任务模式与常规会话在列表和数据归属上分离。
- 删除任务必须删除完整数据（应用层串联：独立库 + orchestrator 级联 + 文件清理）。

### 数据结构

- TaskInstance 是任务功能的中心实体，贯穿三阶段生命周期。
- 独立 SQLite 数据库 `task-instances.db`，与 orchestrator.db 分库，逻辑外键关联。
- 新增 `active_run_id`/`last_run_id`/`run_status` 关联执行实例。
- 新增 `planner_agent_id` 明确 agent 驱动链路。
- 后端 canonical 统一为 `current_phase = "execution"`（消除 "graph" 别名）。
- 执行阶段三层模型：主进程（引擎）+ 主任务会话（task_event 投影）+ 子代理会话（node_attempt.session_id）。

### 容器架构

- `React.lazy()` + `Suspense` 动态加载 TaskPhaseContainer，chat-page 仅新增约 30 行（不含 useChatSession 抽取）。
- useChatSession 抽取为独立工作项（3-5 天），完成后 chat-page 重构为消费方。
- TaskWorkbench 编排层废弃，子组件原地保留被新容器复用。
- 执行阶段三维模型：展现形式（canvas/split/chat）× 会话范围（主任务/节点）× 主进程状态。
- 阶段切换联动契约：切换 = 改变 useChatSession 的 sessionId + readOnly 入参，组件不重建。
