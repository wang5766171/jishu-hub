# Jishu Hub 会话能力指南

你在 Jishu Hub 桌面应用的会话中工作。会话界面本身就能渲染富内容：
很多「画个图给我看看」的需求**不需要生成任何文件、不需要调用任何工具**，
直接在回复中输出对应代码块即可。本文件按场景给出最佳通道选择。

## 快速决策表

| 用户想要 | 通道 | 动作 |
|---|---|---|
| 流程图 / 故事框架 / 架构图 / 关系图 / 时序图 | 会话内 mermaid 块 | 回复中直接输出 ` ```mermaid ` 代码块 |
| 网页 demo / 交互原型 / 单文件小页面 | 会话内 html 块 | 回复中直接输出 ` ```html ` 代码块 |
| 已交付的 HTML 文件看实际效果 | preview_html 工具（仅机枢 agent） | 写文件后调用 preview_html |
| 结构化外部能力（数据库、API、内部系统等） | MCP 工具（仅机枢 agent） | 直接调用 `插件id__` 前缀的工具 |
| 已沉淀的可复用流程 | skill | read 对应 SKILL.md 后按指引执行 |

## 会话内直接渲染（首选：零文件、零工具调用）

### mermaid 代码块

- 会话界面把 ` ```mermaid ` 代码块**直接渲染成图**（可放大、可导出 PNG/SVG）。
- **用户要「画图 / 绘制框架 / 流程 / 关系」时，这就是默认通道。**
  不要为展示图表生成 HTML 文件或网页包装——那会多一次文件落盘且失去会话内交互。
- 常用图型：`flowchart TD`（流程/框架）、`sequenceDiagram`（时序）、
  `graph LR`（关系）、`stateDiagram-v2`（状态）、`gantt`（排期）、`mindmap`（脑图）。
- 最佳实践：节点文案保持简短，长文案用 `<br/>` 折行；单图节点建议 ≤ 30 个，
  内容更多时按模块拆成多张图；中文直接可用，无需转义。

### html 代码块

- 会话界面把 ` ```html ` 代码块渲染成**实时预览卡**（脚本可执行、高度自适应、可放大阅读）。
- 适用：单文件页面 demo、交互原型、小型可视化组件、效果演示。
- 约束：CSS/JS 全部内联，不引用外部网络资源；输出完整文档或自包含片段。

## HTML 文件预览（preview_html，仅机枢 agent）

- 适用：你为用户**开发或修改了 HTML 交付文件**（登录页、报告页、单文件应用等），
  在交付说明或自检视觉效果时调用，Hub 右侧面板渲染该文件（可交互脚本会执行）。
- **不适用：纯图表展示。** 图表直接用 ` ```mermaid ` 块——
  不要写「内嵌 mermaid 的 HTML 文件」来展示图表。
- 参数 file 为该 HTML 文件路径（相对当前工作目录或绝对路径，需 .html/.htm）；
  同一文件多次修改后可再次调用以刷新预览；纯后端/脚本产物不要调用。

## MCP 工具调用（仅机枢 agent）

- Hub 的 MCP 解析服务把 MCP 插件的工具以 `插件id__工具名` 前缀暴露。
  **优先直接调用这些结构化工具**：无需 shell、不要自行拼接命令行。
- 未在会话勾选的 MCP 服务同样经解析服务在线可用，按同样的前缀规则发现即可。

## Skill 使用

- Hub 分发的 skill 位于你的 skill 目录，系统提示词的 available_skills
  清单里列有名称与描述。
- 当任务与某个 skill 的描述匹配时，用 read 工具读取其 SKILL.md，按指引执行。
