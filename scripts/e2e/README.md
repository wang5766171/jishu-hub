# scripts/e2e —— jishu-hub 界面自动化测试

用 Playwright 连上正在运行的 jishu-hub（Windows 版，WebView2），像真人一样点按钮、打字、拖拽，并把结果写成报告。
只连接、不启动浏览器、不下载浏览器；**不进安装包**（见文末「打包守卫」）。

## 在一台新电脑上跑（四步）

```bash
# 1. 取得仓库并装依赖（Node.js 版本要求与仓库 README 一致：22.19+ / 24+）
git clone <仓库地址> && cd jishu-hub && npm install

# 2. 带调试口启动应用（自动找已安装的应用；找不到就先装应用）
node scripts/e2e/start.mjs

# 3. 跑测试
node scripts/e2e/run.mjs --suite smoke          # 基础冒烟：不需要模型和网络；C4c 会切一次访问权限档位（用例内切回）
node scripts/e2e/run.mjs --suite conversation   # 对话：需要已配置可用模型
node scripts/e2e/run.mjs --suite market         # 安装扩展：需要联网
node scripts/e2e/run.mjs --suite fixround       # 评审修复轮：需要模型；其中 F7 另需联网
node scripts/e2e/run.mjs --suite compact        # 斜杠命令与上下文压缩：需要模型；会向测试会话发送很长的消息（占模型用量）
node scripts/e2e/run.mjs --suite search         # 搜索体验、补充轮与工具标签：八块不需要模型；其余要模型（新建两个测试会话）
node scripts/e2e/run.mjs --suite unread         # 未读标记（侧栏绿点）：两条都要模型，各发一条慢消息
node scripts/e2e/run.mjs --suite tasksession    # 任务会话：滚动位置五块 + 切节点一块；前四块要模型（会造任务、会重载页面）
node scripts/e2e/run.mjs --suite approval       # 工具执行审批：同意 / 不同意 / 框架默认不放行 + 还原；要模型；会切访问权限档位（用例内切回）
node scripts/e2e/run.mjs --suite full           # 全量（smoke + conversation + market）

# 不连应用也能跑的自测（改了驱动库或打包守卫之后先跑这两条）
node scripts/e2e/selftest-lib.mjs               # 驱动库：附着校验、等回合的审批三态、用例租约
node scripts/e2e/check-not-bundled.mjs --selftest   # 打包守卫自身

# 4. 看报告：结果目录里的 test-log.md / result.json / screenshots/
```

`full` 不含 `fixround`、`compact`、`search`、`unread`、`tasksession`、`approval`：这几个场景包是 v0.9.8 各需求与评审修复轮新增的专项验证，各自有模型用量或环境方面的代价，单独跑、单独留痕。

常用参数：

| 参数 | 作用 |
|---|---|
| `--project <项目名>` | 在指定项目里跑（默认：应用当前所在项目） |
| `--out <目录>` | 结果输出目录（默认 `scripts/e2e/results/<时间戳>/`，不入库；要留进版本文档就指到 docs 下）。目录已存在时运行开头会告警：同名文件被覆盖、旧文件留在一起 |
| `--only I1,I3` | 只跑指定编号（还原类用例始终执行） |
| `--list` | 列出场景包里的用例 |
| `--checklist` | 输出四字段用例清单（markdown），可直接落 `06-测试清单.md` |
| `--no-lang-switch` | 界面不是中文时不自动切换 |
| `--help` | 用法 |

退出码：`0` 全部通过（跳过不算失败）；`1` 有失败——含还原没做成、界面语言没还原、切走的访问权限档位没调回；`2` 无法运行（没连上应用 / 前置不满足）；`130` 用户中断（Ctrl+C）。

某条用例的前提不满足时（例如只有一个项目、没有可安装的扩展、模型没配置好、当前智能体没有会弹审批的档位），它会标为「跳过」并写明原因，不算失败。有一条断言没法核对（例如运行环境的 Node 没有 `node:sqlite`、读不到未送达账本）而其余都通过时，结果标「通过（有未核对的断言）」并在日志里写明是哪一条——不算失败，也不会静默。

安装类用例依赖网络状况：候选扩展要从网络拉取，同一个候选时快时慢。每个候选最多等 90 秒，五个候选都没装成就跳过，并写明每个候选的结果（冲突卡取消 / 超时 / 失败）。

**「回合还在进行」是用例的前提，不是必然**：暂存、停止、拖拽调序这类用例要求动作发生在回合结束之前。模型快的时候「数到 400」八秒就完了——长任务要给够长度，动作要紧贴首条发送之后。用例的通过条件里要能看出这个前提是否真的成立（例如 fixround 的 F2 记录「暂存时会话头」，没赶上解析前的窗口就换会话重试，仍没赶上则标跳过，不冒充通过）。

**「首次打开」怎么造**：滚动记忆、访问记录、消息缓存都只活在页面内存里，所以重载页面之后的第一次打开，与「启动后第一次进入」「关闭软件重开后再进入」是同一种状态。TS-1、TS-3 用重载来造，不依赖应用是什么时候启动的、之前打开过哪些会话（引擎进程不重启）。

## 怎么加一块积木

在 `blocks/` 里按统一写法加一条，再到 `suites.mjs` 放进对应场景包：

```js
{
  id: "X1",                                   // 编号：截图、日志、清单都对它
  name: "一句话说清测什么",
  feature: "涉及的功能",
  steps: "操作步骤",
  expect: "通过条件",
  needs: "none",                              // none / model / network
  run: async (ctx) => {
    await ctx.app.ensureWorkspace();          // 每块开头：回到工作区、清残留弹层
    // … 用 ctx.app 的助手操作界面 …
    if (前提不满足) ctx.skip("原因");           // 跳过
    return { 关键事实: true };                 // 正常返回 = 通过；抛错 = 失败
  },
  // cleanup: true,                           // 可选，还原类：无论前面成败都会执行，--only 时也带上
  // restore: async (ctx) => { … },           // 可选，本用例自己的还原动作：成败、超时、Ctrl+C 中断都会执行
}
```

三条规矩：

1. **不写死机器信息**。项目名、会话标题、已装扩展、路径都在运行时探测，或通过 `--project` / `--out` 传入。
2. **每块自给自足**。自己新建会话、自己等回合结束，不依赖别的用例先跑。
3. **导航后必校验落点**。切换页面或会话用 `ctx.app.openSession` / `switchProject` / `navClick`，它们会核对是否真的到了目标。

`ctx` 提供：`app`（驱动库）、`page`、`expect`、`state`（跨用例共享）、`shot(名字)`（截图）、`fixture(名字)`（演示文件路径）、`truth(起始时刻, 要找的词?)`（会话记录里的真实消息序列）、`skip(原因)`、`warn(原因)`、`cfg`。

`truth(起始时刻, needles)` 读会话落盘文件，口径如下：

| 字段 | 内容 | 什么时候用 |
|---|---|---|
| `users` / `assistants` | 剥掉注入块、压平换行的用户 / 助手文本（助手每段取前 120 字） | 判断「消息有没有发出、按什么顺序、助手有没有回话」 |
| `rawUsers` | 用户消息**原文**（不剥注入块） | 验证「注入了什么」，比如工具说明块有没有带上 |
| `sequence` | 按落盘顺序的角色 + 文本（前 40 字，空回复也保留一行） | 判断「谁在谁之后」，比如停止后重发的消息后面有没有回复 |
| `timeline` | 比 `sequence` 更全的落盘顺序：另记工具结果（`role: "toolResult"`）与压缩边界（`role: "compaction"`） | 判断「工具结果在回复之前」「压缩排在谁后面」 |
| `tools` | 工具执行结果 `[{ name, isError, text }]` | 判断「工具真的执行了没有」——被拒绝的调用也在这里，`isError` 为真、文本是拒绝原因 |
| `assistantFull` / `assistantEnds` / `assistantLengths` / `assistantAt` | 与 `assistants` 一一对应：每段助手文字的全文（最多 4000 字）、末尾、全长、它在 `timeline` 里的行号 | 看回复的全文、字数、相对工具结果的先后 |
| `found` | `needles` 里每个词在用户 / 助手 / 工具结果里出现没有 | 在整段文字里找一个带编号的字符串，不受截断影响 |

## 等回合与审批

`app.waitTurn(opts)` / `app.waitIdle(stableMs, budgetMs, opts)` 等回合结束时，回合里出现**工具执行审批卡**怎么办由 `opts.approvals` 决定——三态，**默认关闭**（框架不替用户表态）：

| `approvals` | 遇到审批卡 | 返回值 `approvals` |
|---|---|---|
| `false`（默认） | 按 Esc（= 拒绝，与清残留弹层同向），记下每一张；回合结束后**抛错**，报错里列出卡上的工具与命令——用例判失败 | 不返回（抛错） |
| `"allow"` | 点「仅本次允许」。可另给 `approveOnly(card)` 划定放行范围：范围之外的卡点「拒绝」并记下 | `{ setting, clicked, button, items: [{ tool, summary, mode, button, inScope }] }` |
| `"deny"` | 点「拒绝」 | 同上 |

- **「始终允许」任何情况下都不点**——它会把这次批准记进用户的审批记忆，属于持久改动。要放行只点「仅本次允许」。
- **默认关闭的意思**：现有用例的提示词都不让模型调用工具，正常不会遇到审批卡；真遇到了（用户的机器停在审批档、或模型自作主张调了工具），用例会失败并写明是哪一张，而不是悄悄替用户点了允许。
- 自动化对审批卡的每一次表态（点按钮 / 按 Esc、卡上的工具与命令）都记在 `app.approvalLog`，运行结束写进 `test-log.md` 的「副作用」。
- 审批卡不区分会话：它可能是用户别的会话弹出来的，所以报错里带着卡上的内容。
- 注意：输入框里有文字时，产品把停止钮换成发送钮——`turnActive()` 会是假。等回合的期间别让输入框留着内容。
- 这段逻辑有不连应用的自测：`node scripts/e2e/selftest-lib.mjs`（用假的页面对象喂审批卡，核对三态、日志、「始终允许」不点、用例租约）。改了 `waitTurn` 之后先跑它。

访问权限档位的助手：`app.accessMode()`（读当前档位与触发钮文案）、`app.accessModeOptions()`（读菜单里的档位）、`app.setAccessMode(档位文字)`（切换并等触发钮文案变化）、`app.readToolMode()`（读回后端的档位值与 Pi 设置里的审批开关；只把这一个字段带出页面，配置里的密钥不读进测试进程）。切档之前把运行前的档位记进 `ctx.state.accessRestore`，收尾时调 `restoreAccessMode(ctx)`（`kit.mjs`）切回并读回；块上再登记 `restore: restoreAccessMode`，用例超时 / 被中断时运行器替它切回。

## 运行器怎么收场（超时与中断）

- **用例超时**：超时那一刻起，这条用例手里的驱动被停用——它再调任何驱动方法都立即抛「用例已超时」，正在进行的轮询等待（`waitTurn` / `waitIdle` / …）下一轮就退出。它不会带着界面操作（例如按 Esc 关审批卡）活到下一条用例。
- **还原一定会做**：块上登记的 `restore` 在用例结束后一定执行（成败、超时、中断都执行——超时的用例自己的 `finally` 是跑不到的）；`cleanup: true` 的还原用例照常执行。
- **Ctrl+C**：不再开始新用例，当前用例立刻收场，还原类执行完再退出（退出码 130）；再按一次立即退出。
- 用例失败时自动截 `<编号>-失败现场.png` 并记录一行界面状态。

## 前提与限制

- **只支持 Windows**：依赖 WebView2 的远程调试口。
- **界面定位按中文界面编写**。界面不是中文时，运行器会临时切到中文，结束后还原并读回核对。
- 应用必须已完成首次引导、进入主界面。
- 开发模式请自己带环境变量启动：`WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS="--remote-debugging-port=9222" npm run tauri dev`，再跑 `run.mjs`。
- **开发模式下改了源码，先确认页面真的加载了新代码再跑**：开发实例长时间运行后热更新会跟不上（页面还停在旧代码上，测出来的是旧行为）。改完代码后看一眼页面有没有重新加载；拿不准就重启开发实例。
- 会话记录默认从 `~/.jishu-agent/agent/sessions` 读取，位置不同时设环境变量 `JISHU_AGENT_SESSIONS_DIR`。
- 未送达账本行数的核对（EC-4、EC-12）依赖 Node 的 `node:sqlite`（22.5 以上）；没有的时候这两条断言标「未核对」并写明原因。

## 测试会动什么

跑之前先读这一节。测试连的是**你平时用的那个应用实例**，动的是真实环境。

- **会切「访问权限」档位**（冒烟的 C4c，`approval` 的 AP-1~AP-3）：切档写 Hub 状态和 Pi 设置里的 `toolApproval`，产品行为上还会重启该智能体全部会话的引擎进程。用例内 `try/finally` 切回原档，`APX-1` 与运行器兜底，切回后读回档位值与触发钮文案核对。有回合在跑时这些用例跳过，不去打断你的回合。运行前从没设置过档位时，切回后后端会留下显式的「完全访问」——行为相同（都不弹审批），日志里如实写出。
- **会建测试会话、占模型用量**：对话类用例都会新建会话，不删。`compact` 每个测试会话两条各约 9 万字符的消息，EC-10、EC-11 另各一条要写 2500 字的慢消息；`approval` 三个对话各让模型执行一条 `echo`；`search` 两个测试会话（一个连发几条短消息，SE-14 一个只发一条）；`tasksession`、`unread` 各有少量。
- **`approval` 会让模型执行一条无害命令**（`echo` 一个带编号的字符串）：AP-1 点「仅本次允许」后它真的执行；AP-2 点「拒绝」；AP-3 由框架按 Esc 拒绝。不落盘、不改任何文件。
- **会新建任务、任务图、节点会话**（留在项目里）：`tasksession` 的 TS-4 每次运行新建一个对话、一张任务图、一个带任务图的任务和两个节点子会话；`tasksession`、`unread` 在项目里一个任务都没有时另造一个。造数的提示词都不让智能体调用工具（图上的节点策略是无工具、审批 never），不往项目里写文件。
- **会往项目里已有的任务会话发消息**：`tasksession` 的 TS-3 每次发一条「数到 600」（TS-1 量不出位置时也发）；`unread` 的 UN-1 发一条慢消息。这些消息留在任务会话里。
- **会重载应用页面**：`tasksession` 的 TS-1、TS-3（造「启动后第一次进入」的状态；引擎进程不重启）；`search` 的 SE-14（回到自己那个会话，按回放路径量工具标签；有回合在跑时不重载）；`fixround` 的 F1、F4 与 `compact` 的 EC-4、EC-12（重开会话核对）。
- **会清未读标记**：切会话、切项目会清掉对应的未读（产品的「查看即已读」行为）；`unread` 的 UN-1 会把任务列表里已有的绿点全部点开；`tasksession` 的 TS-5、TS-6 会打开项目里消息最多的几个会话；`search` 的 SE-15 会打开侧栏搜 `@[` 命中的最多 5 个已有会话。这些不可还原。
- **会真实安装扩展**：市场类用例装完即卸；遇「能力重叠」确认卡一律取消，不会停用已装的扩展（仅 F7 按用户裁决真选「停用并安装」，卸载即自动恢复）。还原用例（P4、FX1、FX2）按「当前实测 − 运行前基线」核对，不只看台账——**运行期间不要在应用里手动安装扩展或装卸精选件**，那样发生的改动会被当成测试残留调回去。
- **会短暂占用系统剪贴板**（附件用例 C2、J5）：占用前先看里面是什么。空剪贴板或纯文字才占用，用后还原并读回（读回一致才算已还原）；里面是图片、文件、别的非文本内容，或者读不出来时**不占用**，回落到合成粘贴事件（走应用同一条粘贴处理链，但事件不是可信事件），报告里写明原因。附件用例会把演示图 `demo-chart.png` 落进当前项目的 `.jishu-hub/session_files/`（产品的附件存储位置）。
- **会清输入框与侧栏搜索词**：运行器在每个用例结束后清空输入框——**你自己没发出去的草稿会被清掉**，跑之前先处理；`search` 的用例会清空侧栏的搜索词。
- **临时切界面语言**：界面不是中文时临时切到中文，结束后还原并读回。
- 侧栏会话很多时（一百多行）页面在开发模式下会明显变卡（会话行每次刷新全量重渲染），用例会莫名「点不动」。测试会话多了请清理，或重启开发实例（长时间运行后页面进程也会变慢）。
- `start.mjs` 启动的应用带着调试口；测完执行 `node scripts/e2e/start.mjs --stop` 关掉**它自己启动的那个实例**，再按平时方式打开即可。

## 启动入口（start.mjs）

| 命令 | 作用 |
|---|---|
| `node scripts/e2e/start.mjs [--port 9222] [--exe <路径>] [--restart] [--timeout <毫秒>]` | 带调试口启动应用。启动时把进程号、路径、端口记在 `scripts/e2e/results/.started.json`（不入库） |
| `node scripts/e2e/start.mjs --stop [--force]` | 关闭**本脚本启动的**那个实例，按进程树关（连同网页进程与引擎子进程）。没有记录、进程已不在、或那个进程号现在不是记录里的那个程序 → 不动任何 jishu-hub 进程。近 20 秒有会话文件在写时拒绝（`--force` 才关） |
| `node scripts/e2e/start.mjs --help` | 只打印用法，不启动应用；不认识的参数直接报错退出 |

三条规矩：

- **调试口上不是 jishu-hub 时拒绝附着**：端口被别的程序占着（Chrome / Edge / 别的 Tauri 应用）时报错退出，不去附着、也不再拉起应用。`run.mjs` 那一侧的页面发现同样只认 jishu-hub 的页面地址（`tauri.localhost` 或开发地址）。换端口：`--port <别的端口>`，并让运行器用同一个端口（环境变量 `JISHU_CDP_URL`）。
- **不覆盖你已有的 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS`**：原参数保留，调试口参数追加在后面；原参数里已经带调试口则以你的为准（不重复加）。
- `--restart` 会关掉正在运行的应用实例（有会话正在写入时拒绝）——那是你自己的实例，确认没有回合在跑再用。

## 打包守卫

测试文件只在仓库里，不进安装包。`npm run build` 会在前端构建之后自动执行 `node scripts/e2e/check-not-bundled.mjs`，检查五处打包来源：

1. `dist/`（前端产物，目录取自 `tauri.conf.json` 的 `build.frontendDist`）：文件名和内容不得出现测试基建字样；
2. `tauri.conf.json` 的打包清单（`bundle.resources` / `externalBin`，含平台分配置）：不得指向 `scripts/` 或 e2e，清单引用的资源展开成实际文件后逐个看；
3. 随包压缩包（`pi-runtime.zip`）：包内文件名不得出现 `scripts/e2e`、`lib-pw`；出现 `playwright` 字样只提示；
4. `src-tauri/resources/**`（编译期嵌入主程序）：文件名与文本内容；
5. `src-tauri/nsis/*.nsh`（安装脚本）：不得引用 `scripts/` 或 e2e。

任一处命中就中止打包。**产物缺失也按失败**（不再「跳过」）；压缩包的目录解析不出任何条目同样按失败。守卫每次被调用都先自测一遍，自测不过直接中止——守卫自身退化会在打包时暴露。`node scripts/e2e/check-not-bundled.mjs --selftest` 可单独看自测明细。

## 连不上应用时

| 现象 | 处理 |
|---|---|
| `无法附着应用` | 先执行 `node scripts/e2e/start.mjs` |
| `调试口 … 上不是 jishu-hub——拒绝附着` | 端口被别的程序占着。换端口：`start.mjs --port <别的端口>`，并让运行器用同一个端口（环境变量 `JISHU_CDP_URL`） |
| 应用已在运行，但没开调试口 | 加 `--restart` 重启（有会话正在写入时会拒绝，等它结束） |
| 找不到 jishu-hub.exe | 用 `--exe <路径>` 指定，或设置环境变量 `JISHU_HUB_EXE` |
| 应用未进入主界面 | 先在应用里完成首次引导 |
| 调试口起不来 | 通常是上一个实例的网页进程还带着「无调试参数」的状态被复用——`start.mjs --restart` 会处理；手动做法是结束所有应用进程后重新执行 |
